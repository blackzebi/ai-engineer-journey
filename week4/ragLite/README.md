# RAG-lite — Q&A over my own study notes (Mini-project #5)

Ask a question in Vietnamese about my AI study notes (weeks 1–4) and get an answer that is
**grounded in the notes and cited**, built on a RAG pipeline written from scratch:
`embedding → pgvector → grounded prompt → Claude`.

This is the "G" (Generate) half bolted onto the retrieval pipeline from `week4/ragPipeline`.
The engineering focus is **not** "make the LLM talk" — it is **making it refuse to make things up**,
and making every claim verifiable.

## How it works

```
question (VI)
   │  embed_query()               sentence-transformers, multilingual MiniLM, 384 dims
   ▼
 vector ──► pgvector: ORDER BY embedding <=> query LIMIT 3  ──►  top-3 chunks (+ similarity)
                                                                        │
   answer + [1][2][3] citations  ◄──  Claude (messages.create)  ◄──  prompt(context + question)
```

The same embedding model must be used for **both** ingestion and querying — otherwise the stored
vectors and the query vector live in different semantic spaces and retrieval silently returns junk.

## Stack

- Python 3.10+
- **PostgreSQL 16 + pgvector** (Docker) — vector storage and top-k search via the `<=>` cosine operator
- [`sentence-transformers`](https://www.sbert.net/) — `paraphrase-multilingual-MiniLM-L12-v2` (runs locally, good for Vietnamese)
- **Anthropic Python SDK** — `claude-haiku-4-5` for generation

## Run

```bash
# 0. Start Postgres and ingest the notes (once)
cd week4/pgvector && docker compose up -d
cd ../ragPipeline && python ingest.py

# 1. Ask a question
cd ../ragLite
```

## Anti-hallucination design

Three mechanisms, each doing a different job:

1. **Grounding** — the system prompt restricts the model to the retrieved passages only, so it
   cannot fall back on vague pretrained knowledge.
2. **A legitimate escape hatch** — the model is explicitly allowed to say *"I couldn't find this in
   the documents."* Without that permission, "must answer" outweighs "must be correct" and the model
   fabricates to fill the silence.
3. **Citations** — passages are numbered `[1] [2] [3]` inside the context, so the model only has to
   copy the number back. Every claim maps to a file the reader can open and check.

## Eval results (5 cases)

A crude but real eval: 3 questions the notes **do** answer, 2 they **don't**. Generated by
`python rag_qa.py --eval`.

| # | Question | Expected | Result |
|---|---|---|---|
| 1 | asyncio trong Python dùng để làm gì? | answerable | ✅ PASS |
| 2 | Embedding là gì và dùng để làm gì trong semantic search? | answerable | ✅ PASS |
| 3 | Vì sao phải chunk (chia nhỏ) tài liệu trước khi embed? | answerable | ✅ PASS |
| 4 | Giá cổ phiếu Apple hôm nay là bao nhiêu? | no_answer | ✅ PASS |
| 5 | Cách nấu phở bò truyền thống gồm những bước nào? | no_answer | ✅ PASS |

**5/5 PASS.** The pass criteria are deliberately mechanical: an `answerable` case passes if the
answer is not the refusal string and carries at least one source; a `no_answer` case passes only if
the model produces the refusal string exactly. This measures *refusal behaviour*, **not** answer
quality — that still needs a human read. Proper evaluation (golden dataset + LLM-as-judge) comes in
week 7.

## Limitations and what I'd improve next

Observations from the run above, worth being honest about:

- **Similarity scores are modest (0.60–0.65).** Multilingual MiniLM produces lower absolute cosine
  scores on Vietnamese queries. Ranking is still correct, but the raw number is only meaningful
  *relative to the same corpus and model* — not as an absolute confidence.
- **Sources [1] and [2] are the same file.** Two adjacent chunks from one document both ranked
  highly, which wastes a citation slot. Deduplicating by source, or merging neighbouring chunks,
  would give the model wider coverage for the same token budget.
- **No reranking yet.** Retrieval is pure vector similarity. Hybrid retrieval (BM25 + vector) and a
  cross-encoder reranker are the week-6 upgrade.
- **The refusal check is case-sensitive string matching** — brittle if the model paraphrases. A
  more robust check would normalise case or ask a judge model.
- **Sources are still printed on refusals**, which reads oddly; they should be suppressed when the
  answer is the refusal string.

## Interview talking points

- "RAG is retrieval plus a grounded prompt — the hard part is the prompt contract, not the API call."
- "Giving the model permission to say 'I don't know' is the single highest-leverage change against
  hallucination; without it, the model treats answering as more important than being correct."
- "Every answer cites a source file and a similarity score, so any claim can be traced back and checked."
- "I test refusal behaviour explicitly: two of my five eval cases are questions the corpus cannot
  answer, and passing means the system declines."
